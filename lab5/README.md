## Опис реалізованого функціоналу

### File-based маршрутизація

У застосунку використовується Expo Router. Маршрути створюються через файли в папці `app`. Папка `app/(auth)` використовується для публічних екранів входу та реєстрації, а `app/(app)` містить захищені екрани застосунку. Групи маршрутів у дужках потрібні для логічного розділення екранів і не впливають на URL.

### Контекст авторизації

У файлі `context/AuthContext.jsx` реалізовано глобальний контекст авторизації. Він зберігає `isAuthenticated` і `user`, а також надає функції `login`, `register` та `logout`. Кореневий layout `app/_layout.jsx` обгортає застосунок у `AuthProvider`, тому стан авторизації доступний різним екранам.

### Екрани входу та реєстрації

Екран входу містить поля для email і пароля, кнопку `Увійти` та посилання на реєстрацію. Екран реєстрації містить поля для імені, email, пароля та підтвердження пароля. Між екранами можна переходити за допомогою `Link`.

### Захищені маршрути

У файлі `app/(app)/_layout.jsx` перевіряється значення `isAuthenticated`. Якщо користувач не авторизований, повертається `<Redirect href="/login" />`. Після успішного входу або реєстрації користувач потрапляє до каталогу товарів.

### Каталог товарів

Товари зберігаються в масиві у файлі `data/products.js`. На головному екрані каталог відображається через `FlatList`. Кожна картка товару містить зображення, назву, короткий опис, ціну та текст `Детальніше`. Також на екрані є привітання користувача і кнопка виходу.

### Перехід на деталі товару

Для переходу на сторінку деталей використовується `Link asChild` у компоненті `ProductCard`. URL має вигляд `/details/1`, `/details/2` і так далі. Після натискання на картку відкривається сторінка конкретного товару.

### Динамічний маршрут

Динамічний маршрут реалізовано у файлі `app/(app)/details/[id].jsx`. Параметр `id` отримується через `useLocalSearchParams`. За цим `id` у масиві знаходиться потрібний товар, після чого відображається фото, назва, ціна, опис і код товару.

### Обробка неіснуючих маршрутів

Для неіснуючих маршрутів створено файл `app/+not-found.jsx`. На цьому екрані показується повідомлення `Екран не знайдено` та кнопка для повернення на головну сторінку.

## Контрольні запитання та відповіді

### 1. Яким чином за допомогою Expo Router реалізується перенаправлення неавторизованого користувача?

Перенаправлення реалізується у layout захищеної групи маршрутів. У файлі `app/(app)/_layout.jsx` перевіряється стан авторизації `isAuthenticated`. Якщо він дорівнює `false`, компонент повертає `<Redirect href="/login" />`. Завдяки цьому користувач без входу не може перейти до захищених екранів.

### 2. У чому полягає різниця між використанням компонента `<Link>` та метода `router.push()`?

`<Link>` використовується як декларативний перехід прямо в JSX. Його зручно застосовувати для звичайних посилань або карток, на які можна натиснути. `router.push()` використовується програмно всередині функцій, наприклад після натискання кнопки або після успішної авторизації. Також у застосунку використовується `router.replace()`, щоб після входу замінити поточний екран на каталог.

### 3. Як працюють динамічні маршрути в Expo Router і як отримати передані параметри?

Динамічний маршрут створюється за допомогою файлу з назвою в квадратних дужках, наприклад `[id].jsx`. У цьому застосунку файл `details/[id].jsx` відповідає маршрутам типу `/details/1`. Значення `id` отримується через хук `useLocalSearchParams()`, після чого за ним знаходиться потрібний товар.

### 4. Чому стан авторизації доцільно зберігати у глобальному контексті React Context, а не в локальному стані компонента?

Стан авторизації потрібен одразу кільком частинам застосунку: екранам входу, реєстрації, каталогу та захищеному layout. Локальний стан доступний тільки одному компоненту, тому його було б незручно передавати між екранами. React Context дозволяє зберігати `isAuthenticated`, `user`, `login`, `register` і `logout` в одному місці та використовувати їх там, де потрібно.

### 5. Для чого використовуються групи маршрутів `(folderName)` і як вони впливають на URL-адресу?

Групи маршрутів потрібні для логічного розділення екранів. Наприклад, `(auth)` використовується для входу та реєстрації, а `(app)` для основної частини застосунку. Назва групи в дужках не потрапляє в URL. Тому файл `app/(auth)/login.jsx` має адресу `/login`, а не `/(auth)/login`.
